# 图片输入、默认值与边界检查表

此文件规定必须考虑的维度，不提供任何 Panqu 全局限额。具体格式、字数、张数、大小和默认值只取本次已确认需求；示例符号不是产品配置。只处理本轮涉及的模型、模式和入口。

## 1. 先提取约束，不先编预期

读取需求正文、参数表、错误说明、附注及用户确认答复。按“输入字段 × 模型 × 生成/编辑模式 × 入口 × 条件”分别建行，不能将某一模型限制推广到全部模型。同一参数在不同模式的规则不可合并成一个宽松范围。

约束表固定记录：

| 字段与适用条件 | 需求原文及位置 | 类型、必填、允许值/上下限、单位和开闭区间 | 默认值及生效时机 | 违规处理与副作用预期 | 代码现状/位置 | 边界检查 → 实际用例/证据或缺口 |
| --- | --- | --- | --- | --- | --- | --- |
| 每个独立约束一行；同字段多项限制分行 | 保留原文；缺失写待确认，不能补写成已确认 | 按需求填；未说明的单位/边界单独待确认 | 默认值不等于最小值、首选项、占位符或最近一次值 | 拒绝/忽略/截断/压缩/转换等以需求为准 | 仅描述实现，不替代预期 | 仅填真实 ID 和证据；未映射就写未覆盖 |

## 2. 按输入类型逐项核对

| 维度 | 必须从需求提取及核对的内容 |
| --- | --- |
| 图片格式 | 允许/禁止的扩展名、MIME 与实际可解码格式；大小写、无扩展名、格式不符、损坏/空文件；动图、透明通道等是否支持。列举格式时不能自行添加 JPG/PNG/WebP 等为允许项 |
| 文件大小 | 单张上限/下限、单批合计上限、单位是 byte/KB/KiB/MB/MiB、边界是否包含；限制作用于原文件、压缩转换后文件还是上传请求；请求额外编码开销是否计入 |
| 图像尺寸 | 最小/最大宽高、长边短边、像素总量、宽高比、方向、尺寸倍数；是否自动裁剪/缩放/转码以及顺序；转换后是否仍满足模型限制 |
| 上传数量 | 必传/可选、最少/最多张、单次选择与累计总数、编辑和文生图分别限制；已有图片+新选图片、上传中/失败/删除图片如何计数；重复图片是否去重以及按什么身份去重 |
| 参考图语义 | 各槽位作用、顺序、权重或标签、主图与参考图是否合计；换顺序/替换/删除后的提交顺序；上游多输出和素材库选择是否共用额度 |
| 提示词条数 | 是单条正向提示词、多个输入框、批量提示词、分镜段落还是每图一条；最少/最多条、空条处理、与图片或输出张数是一一配对还是组合；不能把“提示词数量”直接解释成字符长度 |
| 提示词长度 | 正向/负向分别必填与上限/下限；按字、字符、Unicode code point、UTF-16 code unit、字节还是 token；空白、换行、emoji、中文/英文如何计数；有 token 限制须明确 tokenizer/版本或可信计数方法，不能拿字符串长度代替 |
| 提示词规范化 | 是否 trim、合并多来源、替换变量、加前后缀、自动翻译/优化；限制检查在处理前还是处理后；空字符串、全空白、未传和 null 是否等价；超长是禁止、截断还是其他规则 |
| mask/局部编辑 | 掩码是否必填、格式/大小/分辨率、与原图尺寸和对齐关系、透明/黑白含义、空掩码/全遮罩；原图+mask 是否占用参考图总数；仅在本轮编辑模式适用 |
| 输出参数 | 图片生成张数与上传张数分开；可用尺寸/比例/质量/格式、seed 和高级参数的类型、枚举/范围/步长、默认值及互斥关系；没有该能力不要自行启用 |
| 输入来源 | 本轮支持的文件选择、拖拽、粘贴、素材库、历史复用、上游输出、URL/base64 分别核对；相同素材换入口是否仍受同样规则约束；远端不可读或签名失效如何处理 |
| 上传过程 | 上传中能否提交；部分失败/取消/重试/重复选择、删除时仍有在途上传、预览成功但最终上传失败；进度、错误位置/文案、保留/移除文件及恢复方式按需求检查 |
| 适用范围 | 限制是否受模型版本、文生/编辑模式、角色/套餐/权限影响；限制来自产品、上传服务和 provider 的哪一层。三者冲突要报告，不能擅自取最小值并冒充需求 |

## 3. 默认值不能只看页面初次显示

逐字段核对需求规定的默认值和条件：首次进入、创建新节点、首次切到模型、切换模式、刷新、重开历史、复制节点、重置表单分别是恢复旧值、沿用值还是使用默认值。仅对本轮涉及的情形验证，不制造未要求的记忆行为。

对同一字段区分未传、null、空字符串、空数组、0、false；不能用真假判断把合法的 0/false 覆盖为默认值。枚举默认项必须合法；模型切换后旧值超限、不支持或与其他参数冲突时，按需求决定保留、重置、提示或禁止提交，不能自动选第一个选项当产品规则。比对 UI 值、保存值、最终 payload、后端归一化与 provider 实际参数；未观察到某层就标未验证。

## 4. 从每条明确规则派生边界检查

- 数量/整数：0、1、允许的最小值附近与最大值附近；例如已确认闭区间为 L…U，则检查 L−1、L、L+1、U−1、U、U+1，去重并使用合法计量单位。不知道上限就不能编造 U。
- 大小：在已确认计量阶段检查边界前 1 byte、恰好边界、后 1 byte，另检单张合法但整批超限。未知 MB 换算或是否包含边界时先澄清，不能自行定 1000 或 1024。
- 提示词：空、全空白、已确认最短/最长边界及越界；复制粘贴长文本、中文/英文/emoji/换行按已确认计数单位构造。可输入长度和处理后最终长度分开检查；提示词条数另做边界。
- 格式与尺寸：需求允许格式的有效文件、明确不支持格式、扩展名/MIME/内容不一致、损坏文件及尺寸/比例边界。样本应小且可控，不构造解压炸弹或巨大上传；资源成本超出预算时只做已授权离线校验并保留缺口。
- 累计数量：一次上传到上限、已有若干张后再次追加超限、删除后补传、失败后重传、重复素材、拖拽多选；结合需求的计数时机和去重规则判断，不把队列数量当成功数量。
- 联动：切模型/模式后重新校验；输入各自合法但组合超限（参考图+mask、图片数量+提示词配对、尺寸+质量等）按明确规则验证。单因素边界优先，再测已知关联，避免无意义全排列。

## 5. 非法输入不仅检查一个报错

对明确要求拒绝的输入，在已授权环境检查 UI 提示/按钮、实际提交是否发生、后端响应、是否创建任务或上传残留、是否调用 provider/占用额度/扣积分，以及再次修正能否提交。若需求允许先上传后拦截，按其流程判定，不能强制要求零请求。清理/退款是观察项，不授权擅自删除或退款。

绕过前端的后端校验仅能通过已有获准的 test/sandbox 流程；DevTest SAFE 无法执行的写入/生成边界保留未执行，不能改成 GET 验证后宣称同等覆盖。需求缺失、与实现冲突、没生成用例和没执行测试是不同缺口，分别列出。已知输入边界未覆盖时，不得汇总成“图片参数全部通过”。
