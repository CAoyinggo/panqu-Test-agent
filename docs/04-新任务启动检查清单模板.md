# DevTest 通用任务启动检查清单

> 本清单确认测试输入和能力，不提供固定业务场景、接口、账号、参数或流程。

## 1. Requirement

- [ ] Requirement 来源和版本已记录。
- [ ] Acceptance Criteria 可判定并可追溯。
- [ ] 冲突事实已解决或明确阻断。
- [ ] Unknowns 已登记，不使用模板默认值补齐。

## 2. Business Model

- [ ] Actor / Role 已识别。
- [ ] Tenant / Project / Resource / Owner 关系已识别。
- [ ] Business Flow、State、Business Rule、Dependency、Risk 已投影。
- [ ] 多 Actor、多 Resource、多 Scope 没有被折叠。

## 4. Runtime Capability

- [ ] Environment 由运行时显式提供。
- [ ] 每个 Step 有匹配 Processor。
- [ ] 每个 required Evidence 有 Observer。
- [ ] Test Data、Dependency 和 Preflight 可解析。
- [ ] Prepare/Cleanup Hook 已在 allowlist 注册。
- [ ] Policy 允许计划中的真实副作用。

## 5. Oracle 与 Evidence

- [ ] Expected Response、State、Side Effect 分层表达。
- [ ] Negative Case 包含 Non-Mutation 证明。
- [ ] Assertion 关联 Fact 和 Evidence Requirement。
- [ ] Evidence 缺失不会降级成 PASS。

## 6. 标准化

- [ ] 未使用项目或产品专属 Test Type。
- [ ] 未引用单功能模板或固定业务流程。
- [ ] 未在标准资产中写入固定地址、凭据、账号、接口或字段。
- [ ] 标准化 Gate 已通过。

确认后进入：`Requirement → Business Model → Business Scenario → Dynamic Test Dimensions → TEST_CASE_V2`。
