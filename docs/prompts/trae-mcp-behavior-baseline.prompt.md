# TRAE MCP 现有行为固化 Prompt

将下面代码块完整交给本地代码智能体或 TRAE 使用。该 Prompt 会实施第一阶段：只补必要的契约测试与固定样例，不重构生产代码。

```text
你是 test-flow 的契约测试维护者。请在 `/Users/mac/agents/test-flow` 执行“第一阶段：固化现有行为”，为后续重构建立最小、可信的安全网。

这不是新功能建设，也不是报告平台建设。先确认当前真实行为和已有测试，再只补缺失的契约测试与固定样例。不要因为看见更多模块就扩大范围。

## 唯一目标

只固化以下六类已经存在、且与 TRAE MCP 真实使用有关的外部行为：

1. MCP 初始化、工具列表和参数协议；
2. 任务生命周期；
3. 用例执行状态；
4. Coverage Ledger；
5. Acceptance Report；
6. JSON、Markdown、HTML 输出结构。

目标是让后续重构在改变上述行为时能够被测试明确发现。不得借本任务重新设计这些行为。

## 范围与权限

- 唯一工作仓库是 `/Users/mac/agents/test-flow`；如果当前工作区已经是该仓库，以当前仓库根目录为准。
- 不扫描、读取或修改 `/Users/mac/agents/panqu-ai`。
- 保留用户现有未提交改动，不覆盖、不回退、不提交、不推送。
- 允许修改的范围仅限现有 `tests/` 下的契约测试和测试固定样例。确有必要时可以在 `tests/` 内新增一个小型测试文件或 fixture。
- 禁止修改 `src/`、`bin/`、`integrations/`、`mcp-bridge/`、`packages/`、生产配置、package exports、MCP schema 和运行协议。
- 禁止新增依赖、测试框架、通用测试平台、报告生成器、schema 系统、抽象基类或共享“管理器”。
- 如果无法在不改生产代码的前提下测试某项行为，停止该项并报告最小阻塞原因，不要为了可测性擅自重构。
- 不调用真实业务接口，不启动生产服务，不上传文件，不读取密钥，不创建任务，不产生费用。

## 开始前先做减法检查

先读取适用的 `AGENTS.md`、`package.json`、测试配置，以及与六类行为直接相关的入口和现有测试。优先检查并复用这些已有测试，而不是平行新建另一套：

- `tests/integration/devtest-mcp-kernel.test.ts`
- `tests/integration/stdio-mcp-portable.test.ts`
- `tests/integration/stdio-mcp.test.ts`
- `tests/unit/devtest/coverage-ledger.test.ts`
- `tests/unit/devtest/artifacts.test.ts`
- `tests/acceptance/report.test.ts`
- 其他被上述测试直接引用的 helper 或 fixture

在编辑前建立一张简短映射：`契约 → 当前生产入口 → 已有测试 → 缺口`。

遵守以下减法原则：

- 已有测试能够稳定证明的行为，不新增同义测试。
- 多个测试只是在不同文件重复断言同一常量时，复用现有测试；本阶段不做大规模测试目录整理。
- 只导出但没有真实入口的内部类型，不当作外部契约固化。
- 代码行数、注释或文档声称的行为不是运行契约；必须核对实际入口、返回值或序列化结果。
- 发现生产实现之间相互矛盾时，不选择一个“看起来正确”的结果替代其他结果，也不修改生产代码；分别记录当前事实和冲突，交给后续阶段处理。

## 契约固化要求

### 1. MCP 初始化、工具列表和参数协议

从实际对外的 `devtest-mcp` 入口验证，不自行发明协议：

- 初始化能够完成，并返回当前真实协议所需信息；
- 工具列表中实际暴露的工具名称、数量和输入 schema；
- `devtest` action 的真实枚举、必填字段和拒绝的非法输入；
- JSON-RPC 响应与错误的最小稳定结构。

优先扩展现有 stdio/MCP 测试。只保留一条能够覆盖真实公开入口的主测试链路，不再创建第二个 MCP harness。不得调用业务执行；如需 runner，使用现有安全 fake 或 fixture。

### 2. 任务生命周期

基于当前实现固化计划或任务从创建到终态的真实状态和关键不变量，至少核对：

- ID、plan hash、幂等键等对外稳定字段；
- 合法状态变化和终态后的查询结果；
- 重复请求或状态查询不会凭空创建第二个任务；
- BLOCKED、NOT_EXECUTED、COMPLETED 等流程状态与用例结果没有被测试混为一谈。

只测试确定性的内存、临时目录或现有 fake 路径。禁止真实网络、供应商调用和付费任务。

### 3. 用例执行状态

从实际公共模型和序列化结果中确认状态集合，不只读取注释。固化：

- 当前合法状态值；
- 每个状态在 JSON 和报告中的真实表示；
- 用例总数与各状态计数的当前不变量；
- 未执行或缺少证据时不会被悄悄变成 PASS。

如果不同模块对状态含义不一致，新增能够记录各自当前行为的最小 characterization test，并在最终结论中明确冲突；本阶段不统一模型。

### 4. Coverage Ledger

使用一个最小、固定、无业务依赖的输入样例固化：

- requirement/case/evidence 的绑定方式；
- 覆盖、未覆盖、阻塞的当前分类；
- 汇总计数和关键业务结论；
- 相同输入重复计算得到相同结果。

不要创建新的 Coverage 模型，不扩充维度，不追求覆盖所有边缘业务。

### 5. Acceptance Report

复用与 Coverage Ledger 相同或可直接映射的最小样例，固化：

- 当前报告顶层结构和必要字段；
- 用例状态、计数和结论的当前投影；
- 缺少证据或存在阻塞时的真实表现；
- 输入相同则输出的稳定字段一致。

不要借测试修正报告结论，也不要新增报告格式。

### 6. JSON、Markdown、HTML 输出结构

只对外部消费者真正依赖的结构做固定样例：

- JSON：关键对象层级、字段名、类型和枚举值；
- Markdown：标题、固定章节、表头和关键状态文本；
- HTML：文档骨架、关键区块标识和必要的转义行为。

避免把时间戳、绝对路径、随机 ID、排序无保证的数据或整页样式固化为脆弱快照。动态值使用测试侧归一化或结构断言；不要为此修改生产实现。优先使用可阅读的小 fixture，禁止生成大体积 snapshot 和重复的三套输入数据。

## 测试设计约束

- 测试名称必须说明被保护的外部契约，而不是内部实现步骤。
- 每个测试只保护一个清晰契约；可用参数化测试消除重复。
- 固定样例应尽可能小，并由 JSON 或现有 fixture 格式表达；不要复制完整生产报告。
- 不 mock 被验证的对象本身。允许 mock 网络、时间、随机数和外部执行器，但必须调用真实协议适配、状态转换或渲染代码。
- 断言公共输出，不断言无关私有调用次数。
- 不为了让测试通过而更新期望值；先确认变化是当前真实行为还是测试误判。

## 执行与验证

1. 先查看现有脚本内容和工作区状态，确认命令不会访问外部系统。
2. 先运行与修改文件直接相关的最小测试集合。
3. 再运行六类契约对应的现有相关测试；不要运行全仓库测试、coverage、E2E、性能测试或真实业务测试。
4. 使用仓库已有依赖和 test runner；不得通过 `npx` 临时下载、不得安装依赖。
5. 如果 MCP 公开入口测试必须依赖现有 build，可运行仓库已经定义且确认安全的本地 build；说明它生成了哪些本地产物。不要发布或打包上传。
6. 记录实际命令、退出码和失败测试名。禁止把未运行写成通过，禁止用格式校验代替行为验证。

## 停止条件

出现以下任一情况时停止扩张：

- 六类契约都已有可信测试，无需新增；
- 剩余缺口必须修改生产架构才能测试；
- 当前实现存在冲突，无法在不做产品决策的情况下确定唯一预期；
- 测试会触发真实业务、外部写入、密钥读取或费用。

这些情况应如实报告，不要自行增加抽象或功能绕过去。

## 最终交付格式

只输出以下五部分，保持简洁：

1. `固化结果`：六类契约分别为“已有覆盖 / 本次补齐 / 仍有缺口”。
2. `改动文件`：每个测试或 fixture 为什么必要；没有改动就明确写“无需新增”。
3. `真实测试结果`：实际命令、通过/失败数量、退出码。
4. `发现的现有冲突`：只列有源码和测试证据的事实，不在本阶段修复。
5. `未做事项`：明确未修改生产代码、未新增平台能力、未访问业务系统、未执行付费任务。

不要生成新的测试报告页面、仪表盘、覆盖率平台或长篇架构文档。完成上述安全网后立即停止。
```
