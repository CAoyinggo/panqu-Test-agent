> **通用模板说明**：以下均为通用模板，使用时请将所有 `{占位符}` 替换为实际业务数据。示例以 `wan3`（视频生成）业务为例，仅作演示，实际使用时请替换为您的业务名（如 user、order、payment）。

## 二、数据需求清单模板

> 用途：每次测试执行前，明确本次测试需要哪些数据、来源是什么（可复用 / 需你提供），避免执行中断。

### 清单格式

| # | 数据项 | 用途 | 来源（可复用 / 需提供） | 状态（已备 / 待提供） | 备注 |
|---|---|---|---|---|---|
| 1 | 登录态（auth cookie + JWT） | API 鉴权 | 可复用：`test-Configuration/session-cookies.json` | 已备 | 含 test / preonline 两环境 |
| 2 | 项目 ID | 提交/查询任务 | 可复用（随登录态） | 已备 | 各环境值不同（test={项目ID}、preonline={项目ID}），按实际环境填写 |
| 3 | 任务名 | 任务标识 | 需提供（需求输入） | 待提供 | |
| 4 | 业务场景类型 | 选择任务类型/接口 | 需提供（需求输入） | 待提供 | 按实际业务填写，示例：文生/图生/全能参考/首尾帧/剧本分镜 |
| 5 | 输入内容（如提示词） | 生成内容 | 需提供（需求输入） | 待提供 | 按实际业务决定是否必填 |
| 6 | 参考素材地址 | 有参考素材的业务 | 可复用：测试素材库 `/Users/mac/agents/Test-panqu/` | 待确认 | 图片 `photo/`、音频 `audio/`、视频 `video/`；脚本自动扫描上传 |
| 7 | 参数（如分辨率/时长/比例） | 提交参数 | 需提供（需求输入） | 待提供 | 示例：{分辨率} / {时长} / {比例} |
| 8 | 计费规则 | 计费断言 | 可复用（代码/已接入清单） | 已备 | 示例：{单价}，如 720P=60积分/秒 |
| 9 | CSRF token | 提交鉴权 | 脚本自动获取 | 已备 | 从页面 HTML 提取 |
| 10 | 数据库访问 | SQL 查库（可选） | 需提供（如需深度验证） | 待提供 | 可选 |

### 使用流程

1. **我填写清单**：根据需求与代码分析，列出本次需要的全部数据项，并标记来源。
2. **你确认/补充**：逐项确认；标"需提供"的项目由你补充（尤其素材路径、参数）。
3. **执行**：清单全部"已备"后，运行 `node dist/bin/run-test.js --task tasks/{任务名}.json`。
4. **缺口处理**：执行中若发现清单未覆盖的数据缺口，我暂停并向你索取，补齐后继续。
