# 画布组件输入、默认值与边界检查表

按本轮组件和需求范围使用，不给 Panqu 预设节点数、连线数或素材限制。模型节点的图片格式/大小/数量、提示词条数/长度及媒体参数必须同时按对应媒体 Skill 的输入检查表提取，不能因为经由画布输入就免检。

## 1. 组件输入约束表

按“组件 kind/type × 端口/字段 × 模式 × 输入来源/状态”建行，独立约束分别记录；同名字段在不同组件不默认同规则。读取需求正文、表格、附注和用户确认答复，不能只看组件截图或现有 manifest。

| 字段/端口与条件 | 需求原文及位置 | 类型、必填、枚举/范围、单位及边界 | 默认/恢复/合并规则 | 无效时处理与副作用 | 当前代码位置/行为 | 边界检查 → 实际用例/证据或缺口 |
| --- | --- | --- | --- | --- | --- | --- |
| 每个独立约束一行 | 缺失、冲突、不可读分别标明 | 未写不等于无限制或允许所有类型 | 初始默认、旧数据恢复和上游派生分开 | 按明确需求填写，不推测自动截断/删除 | 代码现状不能代替需求 | 没映射就写未覆盖，不伪造 ID |

## 2. 节点/组件输入检查

| 维度 | 必须核对的内容 |
| --- | --- |
| 字段类型 | string/number/boolean/array/object、必填、空值、缺省、null、0、false、空数组；数字字符串是否转换、整数/小数、枚举、最小最大与步长；客户端和保存/执行接口对类型的理解 |
| 端口类型与数量 | 接收/输出 TEXT、IMAGE、VIDEO、AUDIO 或其他已支持类型；单值/多值、单端口与节点总连线限制、最少输入、同来源重复连线、多端口共享额度、断开后状态 |
| 文本来源与合并 | 手动提示词、上游文本、模板/变量和素材标签的顺序、分隔符、覆盖还是追加、空文本处理；条数与长度在合并前还是最终提交时校验，计数单位由需求确定 |
| 素材来源与计数 | 手动上传、粘贴、拖拽、素材库、历史、上游结果；计数基于节点、连线、结果条数还是选中素材；同一节点输出多张/多段、不同节点引用同一资产、去重身份、顺序、分角色/合计上限 |
| 媒体限制传播 | 上游可连接/已生成不代表下游可接受；下游仍检查格式、大小、尺寸、时长、数量和模式能力；取值阶段是预览、保存还是执行快照，按需求明确 |
| 默认参数 | 新建节点、切模型/模式、复制粘贴、重置、撤销/重做、打开旧画布和版本恢复分别沿用/恢复/重置什么；从上游派生与手工设置哪个优先；默认值自身是否落在合法域 |
| 图结构限制 | 本轮涉及的节点/边/分组数量、分组嵌套、重复连接、自环/循环依赖、孤立节点和禁止的类型组合；只按需求明确允许/拒绝，不自定“所有画布都禁止环” |
| 组件交互参数 | 宽高范围、缩放步长、可编辑字段长度、选择数量、拖拽/多选/批量操作限制；只改布局且不涉及生成时，媒体参数可以标范围外并说明 |
| 上传与输入就绪 | 上传中、失败、取消、重试、上游运行中/失败/输出缺失、选中素材失效时是否允许执行；晚到输出/上传完成不应按猜测替换当前输入，依据明确任务/状态规则核对 |
| 执行快照 | 执行前未保存参数与连线如何合并、输入检查和参数快照的顺序、执行期间修改是否影响在途任务；同步/版本冲突应与模型参数非法分开识别 |
| 旧数据兼容 | 缺字段与旧默认值、废弃字段、旧模型/端口、超出新上限的历史数组；加载、复制、版本恢复后如何迁移/提示，不能静默丢资产或连线以通过校验 |
| 校验与反馈范围 | 当前节点、整个分组、全图执行分别在哪一层阻止或跳过；报错定位、文案、保留输入、下游任务及扣费影响；前端拦截和后端执行器必须分层验证 |

## 3. 明确边界和组合案例

- 数量/长度为已确认闭区间 L…U 时，检查空/0、最小值两侧、最大值两侧；连续数值按需求精度/步长取邻值；枚举验证合法集合及明确非法值。未知上限或单位先提问，不编数值。
- 从单节点少量输入递增到上限、再追加一个；另外验证多上游每个都合法但合并后超限。没有需求上限时不能制造任意“性能门槛”作为产品失败。
- 一个上游返回多项、仅选部分输出、重复资产、多端口合并、重排与断线后重连，按需求检查最终条数/顺序/去重；仅数连线条数不能证明素材数量正确。
- 提示词输入框自身合法，但合并上游、模板、变量后超过长度/条数限制；检查最终发送文本。中文/英文/emoji/换行按已确认计数单位测试，不把字数、字符数和 token 混用。
- 新建、复制、撤销/重做、保存重开、版本恢复、模型/模式切换各选本次影响的路径；观察 UI、图设计数据、执行 payload 和实际任务参数是否符合规定，不将运行态混成设计默认值。
- 错误单参数先独立复现，再检查本轮明确的跨参数依赖；不要一次改多个非法项导致不知道哪条规则起作用。

## 4. 不让非法输入的副作用漏检

只有需求明确拒绝时才用“应拒绝”作为预期；若要求裁剪、转换、提示保留或部分执行，按对应规则判断。观察错误是否定位到正确节点/端口，是否允许纠正，是否创建本不应创建的任务、影响其他节点/共享数据或扣费。后端校验缺证据不等于通过，也不能只因前端有 disabled 就判通过。

需求限制明确但 DevTest 没有生成对应边界时列为未覆盖；未经授权不能自行组请求、运行画布、触发计费或改写旧数据。缺失/冲突规则集中确认，保留未执行边界；不得用“画布功能正常”概括未验证的输入限制。
