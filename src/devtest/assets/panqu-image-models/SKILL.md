# Panqu 图片与模型

先定位子仓库、分支、宿主与实际入口，按 [代码入口](references/code-map.md) 追踪生成或编辑链路。画布图片节点任务同时读取可用的 `panqu-canvas`；仅编辑器笔刷交互不等于模型接入，按涉及部分裁剪检查范围。与视频共用能力或跨媒体流水线发生变化时，再组合 `panqu-video-models`。

## 模型更新的检查重点

每次读取当前模型配置和调用链，不固化模型白名单、provider 名单或价格。先记录“旧能力 → 新能力 → 影响入口与验证证据”。

- 身份与列表：display_name、alias/name、真实模型名、配置 ID、enabled、权限、缓存更新和旧记录恢复。UI 选项值不能替代 provider 模型名；确认配置 ID 从列表到任务、计费都保持一致。
- 类型与能力：image_generate 与 image_edit 分开；有参考图时不能继续选只支持文生图的模型。能力 undefined 与空数组/false 的含义按当前协议核对，不把未知自动开放成全部支持。
- 模式与约束：参考图数量和顺序、mask、尺寸/比例、生成张数、支持格式、模式组合与交集。切模型/模式、增删参考图后，选择项、默认值与最终 payload 需一致；不支持的旧参数不能残留提交。
- 任务全链：列表/选择 → 参数归一化 → 后端配置与 provider 路由 → processor/查询 → 图片资产 → 结算。新增一个 UI 选项或枚举不是完整接入。
- 结果：URL/base64 的返回分支、存储与可访问性、原图/缩略图、尺寸与张数、选中输出、历史恢复和缓存。提交成功、返回 URL 字符串、mock 图片都不能单独证明真实生成完成。
- 异常：不支持的输入、参考图不可读、重复提交、取消/超时、失败重试、过期回调、生成成功但保存或计费失败。积分扣退及重试规则需要已确认需求，不能拿旧模型价格补空白。

## 工作与证据

用户要求开发才修改业务代码；审查、诊断和自测保持实现只读。缺失的产品规则集中澄清，区分需求预期、代码现状与 UNKNOWN。不要把对图片质量的主观印象当作未定义的通过标准；质量要求需给出用户认可的可判断依据。

验证本次新能力、参数边界、切回旧模型、旧记录及必要的失败副作用。纯函数、源码契约、mock 和真实图片生成的证据分层交付；离线测试通过不能覆盖未经执行的产品要求。

DevTest 可用时读取主 `devtest` Skill，保持需求映射、计划一次确认、直接执行和证据门禁；不要另写请求绕过 SAFE 内核。缺少工具或真实生成权限时仅做已授权的本地验证并列出缺口，不能宣称业务 PASS。

不要因“图片功能”调用助手的 imagegen 工具；这里维护的是 Panqu 产品能力。付费生成、线上资源写入、数据库改动、真实 worker 与部署都需要对应授权环境。Feishu/Lark 需求文档使用 panqu-ai Keychain 凭证并严格保密，权限不足时关闭访问并说明缺项。
