## 二、关键场景测试步骤与执行指引

### 场景 1：全量模型全链路验证 (TS-15)
- **前置**：模型（如 Wan 3.0 ID=84）设置 `is_newapi_global = 1`；
- **执行**：使用测试账号发起任务请求（携带唯一前缀 `devtest_wan3_e2e`）；
- **验证**：
  1. 检查任务记录 `pq_aivideo_new.extra`，确认包含 `newapi_model: 'wan3.0-video'` 与 `newapi_org_id: 0`；
  2. 确认任务分流至 NewAPI 阿里万相渠道（渠道 #36）；
  3. 确认任务完成后用户积分实扣准确（如实扣 28 积分）。

### 场景 2：非全量模型的组织路由隔离 (TS-11)
- **前置**：模型设置 `is_newapi_global = 0`；
- **执行**：
  1. 分组内用户（所属组织在 `pq_newapi_route_group_org` 绑定了路由组）发起请求；
  2. 未分组用户（所属组织未绑定路由组）发起请求；
- **验证**：
  1. 分组内用户成功分流至对应 `newapi_group`；
  2. 未分组用户前置回退走历史直连线路，不走 NewAPI。

### 场景 3：分流重试与兜底边界 (TS-20)
- **前置**：触发上游 NewAPI 503 或渠道调用超时；
- **执行**：分别发起 Seedance 2.0 (SD 系列) 与 Wan 3.0 (非 SD 系列) 的异常任务；
- **验证**：
  1. Seedance 任务在 `pq_aivideo_new` 中标记 `is_need_fallback = 1`，出现在分流重试列表；
  2. Wan 3.0 任务直接标记状态失败，**不出现在分流重试列表**。
