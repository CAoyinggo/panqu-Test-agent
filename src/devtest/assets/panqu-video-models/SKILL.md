# Panqu 视频与模型

先确定子仓库、当前分支、实际宿主及任务类型，再按 [代码入口](references/code-map.md) 追踪当前调用链。若通过画布节点操作，同时读取可用的 `panqu-canvas`；若修改的是共用图片能力或图片生成链路，再组合 `panqu-image-models`，不是看到参考图片就默认全量检查图片生成。

## 联合验证与交付

测试方案不能只有页面操作。每条适用规则关联代码入口、边界或状态转换的实际本地测试、API/页面用例和业务结果；源码扫描、函数执行、mock、真实调用分层记录。先审查已有测试和依赖副作用，再运行安全的相关本地测试；没有 runner/安全执行条件就列具体缺口，不盲跑 build/deploy，也不把源码正则测试当运行行为。前端拦截与后端校验分别验证。

使用 DevTest 时完整读取同目录主 Skill 的 `../devtest/references/combined-validation.md` 和 `../devtest/references/markdown-handoff.md`。主 Skill 不在同目录时从本项目实际 DevTest 安装定位；无法取得则明确缺项。交付沿用测试用例全量表和固定七章单表报告，不能用自由截图报告取代；未执行、复测前失败和真实结算缺口不得因页面成功消失。

## 输入约束先于测试计划

涉及模型、上传、提示词、生成参数或默认值时，必须完整读取 [视频输入与边界检查表](references/input-constraints.md)，在计划前形成逐项约束表；参考图片本身的格式、大小和数量不能漏掉。每行写清字段、适用模型/模式、需求原文位置、规则和单位、默认值、代码现状、边界检查及覆盖状态。

同时提取需求表格、注释、附录和已确认答复；不可读内容标为未读取。已明确限制不重问，缺失/歧义/冲突集中提问。未写不等于无限制；不能从其他视频模型、前端占位文字或当前代码推定业务默认值。仅本轮不涉及的维度标“不适用”并写理由，不强迫无关模式进入本次需求。

已确认限制逐条关联计划中的实际用例和证据；DevTest 未生成的保留未覆盖，不自造用例 ID 或绕过 SAFE 执行。此处是 Skill 的检查要求，不是产品运行时参数校验器；未知规则和未执行边界不能算通过。

## 每次新增模型重新核对

不要维护封闭的模型名称名单，也不要把前一个模型的默认参数当成新模型能力。根据本次需求和当前配置形成差异表：模型身份、可用类型、权限/启停、能力、参数约束、后端处理、计费和结果。

- 身份链：展示名、alias/name、实际 provider 模型名、配置 ID 和路由键分别是什么。Nuxt 的 UI 选项值与后端真实模型名不是同一字段；检查 panqu_selmodels_id 等配置标识是否贯通。
- 可见性：enabled、disabled_reason、permission、类型筛选、缓存刷新、默认回退和旧记录选择恢复。确认禁用模型不会因缓存或旧参数再次提交。
- 生成模式：文生、图生、首尾帧、多参考、视频编辑及 omni 必须以显式能力为依据；不因模型属于“视频”就开启所有模式。能力缺失、false、空列表要按当前协议分别处理。
- 参数：duration 范围/枚举、分辨率、比例、参考图片数量与顺序、参考视频/音频、必填项和互斥项。切模型或切模式后，按需求处理失效旧值；不能猜测应自动清空、截断或回退，UI 与最终 payload 都要检查。
- 任务链：模型列表 → 参数提交 → PHP 路由/配置 → 实际 Go registry/processor → 查询调度 → provider task ID/状态 → 结果资产 → 积分结算。只检查需求涉及的服务，但不能因为下拉框出现新名字就认定接入完成。
- 异常链：不支持的参数、重复提交、超时、取消/重试、迟到回调、跨项目/任务串状态、生成成功但存储或结算失败。重试与扣退积分应按已确认业务规则验证幂等，不推测价格或免费重试规则。
- 结果链：可访问视频、时长精度、尺寸、封面/播放、历史重新打开及节点选择。返回任务 ID 或 HTTP 200 仅说明提交响应，不代表视频已生成。

## 交付与边界

将“需求预期、代码现状、未知规则”分开；缺失的时长/参考数/计费规则向用户集中澄清，不从已有模型复制答案。开发请求才改业务代码；审查、诊断、自测不顺便修实现。

验证矩阵覆盖本次新增/改变能力、切换回旧模型、旧记录恢复，以及相关失败/副作用。已有测试或 mock 能证明的范围单独写明；没有真实结果资产和确定性 Oracle，不能宣布视频业务 PASS。

在 DevTest 中先读取主 `devtest` Skill，按需求生成计划、一次确认后直接执行，保留未覆盖项；本 Skill 不授权替换用例或绕过 SAFE 内核。没有该工具时可做仓库已有离线验证，明确尚缺的集成证据。

不要自动调用付费生成、启动真实队列 worker、写数据库或运行部署脚本。真实生成和结算验证需要明确授权的 test/sandbox 流程与预算；无法访问时报告准确缺项，不借生产账号绕过。Feishu/Lark 文档访问遵循 panqu-ai 的 Keychain 凭证规则，不能泄露或复制凭证。
