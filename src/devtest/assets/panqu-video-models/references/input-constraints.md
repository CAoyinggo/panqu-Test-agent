# 视频输入、默认值与边界检查表

此清单用于提取本次需求，不提供通用模型限额。视频功能中的参考图片、参考视频、音频和提示词是不同输入，应分别列明限制；只检查本轮支持的模式，不凭清单新增产品能力。

## 1. 约束记录格式

按“字段 × 模型/版本 × 模式 × 素材角色/入口 × 适用条件”建行；不要把不同模型/模式的限制合并。需求正文、参数表、注释、错误说明和已确认答复均需检查。

| 字段及条件 | 需求原文与位置 | 类型、必填、枚举/范围、单位与边界 | 默认值及触发时机 | 不满足时的处理/副作用预期 | 实现位置和当前行为 | 边界检查 → 实际用例/证据或缺口 |
| --- | --- | --- | --- | --- | --- | --- |
| 每个独立约束单独一行 | 已明确直接使用；缺失/冲突写待确认 | 未说明不能默认无限制或沿用另一模型 | 不从占位符、第一选项或最近值猜默认 | 拒绝、忽略、截断、转码等以需求为准 | 代码不是业务 Oracle | 不自造 ID；没生成、没执行、证据不足分开写 |

## 2. 视频功能必须逐项检查的维度

| 维度 | 要提取和核对的具体内容 |
| --- | --- |
| 参考图片格式 | 每个图片槽位允许的扩展名/MIME/真实内容格式，动图/透明图是否支持；大小写、损坏、零字节、伪装后缀/类型的处理；不能自动把常见格式当白名单 |
| 参考图片大小/尺寸 | 单张与合计文件大小、byte/KB/KiB/MB/MiB 及边界包含性；限制作用于原始还是压缩转换后的文件；宽高、像素量、比例、裁剪/缩放规则及检查顺序 |
| 图片数量 | 最少/最多、一次与累计选择；首帧、尾帧、普通参考图、主体/风格图是否分别或合计计数；已有+新选、上传中/失败/删除图片的计数；重复素材是否去重 |
| 首尾帧 | 必填组合、能否仅首帧或仅尾帧、顺序、相同图片是否允许、两帧尺寸/比例是否要求一致；是否与参考视频、多参考模式互斥。输入控件存在不等于模型支持 |
| 参考视频格式 | 容器与视频编码分开，音轨编码/有无音轨、可解码性；扩展名/MIME/内容冲突与损坏文件处理；仅按已明确的编码/容器组合判断 |
| 参考视频大小/时长 | 单个与合计文件大小、数量、单段/总时长、是否含端点、秒/毫秒、可接受精度及是否截取；真实素材时长和 UI 四舍五入显示不得混为一谈 |
| 参考视频画面 | 宽高、分辨率、比例、帧率/可变帧率是否受限、自动转码/缩放的参数与时机；转码前后限制可能不同，不能只看文件大小 |
| 参考音频 | 格式/编码、大小、数量、单段/合计时长、采样率/声道等需求明确的限制；与视频音轨、配音、首尾帧及 omni 模式的互斥/组合；未支持音频则不新增测试能力 |
| 混合素材预算 | 图片/视频/音频各自上限与总素材上限、各角色是否共享额度；同一文件多槽位、同一上游多输出、去重和排序规则；各自未超限不代表合计合法 |
| 提示词数量 | 单条、多条、正向/负向、每段/每镜头分别支持多少；空条、段落合并、与素材/镜头的配对或组合规则。“数量”没有说明是条数还是长度时必须澄清 |
| 提示词长度 | 各提示词字段最短/最长与必填；按字/字符/code point/UTF-16 单元/字节/token 计数；中英文、emoji、换行和首尾空白计数；token 需明确计数方法，不用字符串长度冒充 |
| 提示词处理 | trim、模板、角色标签、引用素材标记、变量替换、自动翻译/优化和系统前后缀；长度校验作用于输入还是最终发送文本；无效引用、空文本及超长如何处理 |
| 生成参数 | 输出时长、比例、分辨率、帧率、生成条数、音频开关、seed、运动/镜头等支持参数的类型、枚举/范围/步长/默认值；上传视频时长与生成视频时长分开 |
| 参数联动 | 时长×分辨率、比例×参考图、模型×模式、音频×视频编辑、素材数量×提示词等组合限制；界面隐藏字段是否仍残留提交；按需求确定合法组合，不默认所有组合可用 |
| 上传与来源 | 文件选择、拖拽、粘贴、素材库、历史复用、URL、上游输出中本轮支持的路径；上传中提交、部分失败、取消、重试、换模型时仍在途的上传；远端链接不可读或过期后的反馈 |
| 适用范围与反馈 | 模型版本、角色/套餐权限、上传服务和 provider 限额；错误文案/位置、按钮状态、保留或清理输入、任务/额度/积分影响。产品和 provider 规则冲突时报告，不能自行用更严格者改写产品要求 |

## 3. 默认值与状态转换

逐字段核对首次进入、新建节点、切换模型/模式、重新打开历史、复制节点、刷新和重置时的默认/恢复/沿用规则。明确未传、null、空值、0、false 和空数组是否等价；不要用通用真假回退逻辑推断业务行为。

对切换前合法但切换后非法的旧时长、比例、素材数量或音频参数，按需求确认是重置、保留提示、转换还是禁止提交。默认值也须满足当前模型与联动约束；不能静默丢掉超限素材或替用户选另一个模型。比对 UI、保存数据、组装 payload、后端归一化、processor/provider 参数，未观察层保持未验证。

## 4. 边界与组合检查的派生方法

- 对已确认整数数量闭区间 L…U：空/0、1、L−1、L、L+1、U−1、U、U+1，按适用性去重；首帧/尾帧/参考图分别测，再测已确认共享总量。
- 文件大小：在需求规定的计量阶段检查边界−1 byte、边界、边界+1 byte；单个合法但累计超限必须单列。单位或包含性不清楚先提问。
- 时长与连续量：使用规定精度/步长 δ 检查 L−δ、L、L+δ、U−δ、U、U+δ，补零/负数/不合法类型（仅当接口契约适用）；枚举时长逐项检查及一个明确不支持值。不得假设所有模型只接收整数秒。
- 提示词条数和文本长度分别测；按确认的计数规则覆盖空白、粘贴、多语言、emoji、换行和处理后超限，不能只验证输入框计数器。
- 格式和媒体元数据：合法组合、不支持的容器/编码组合、损坏文件、格式伪装、尺寸/比例边界；用小型可控样本，不做巨大上传或解压炸弹测试。
- 累计与异步：已有素材后追加超限、删除后补传、失败重试、重复上传、切换模型时旧上传完成；确认素材角色、顺序和总数在最终任务中正确，不能只检查预览列表。
- 联动优先检查需求明确的互斥/依赖和此次变化；合法单参数组合成非法请求也要覆盖，避免无依据全排列或自动发大量付费任务。

## 5. 拒绝输入及未覆盖项

对于明确应拒绝的输入，按需求检查提示、提交/上传请求、后端响应、任务记录、provider 调用、额度和积分副作用，以及纠正输入后是否可恢复。按“上传前拦截”“上传后生成前拦截”等真实需求阶段判断，不将任何请求都视为缺陷。需要观察清理或退积分，不等于获得删除或退款授权。

后端绕过前端校验、真实生成、持久化和计费边界仅在已有获准的 test/sandbox 工作流与预算内验证。DevTest SAFE 无法跑的保持未执行；只查模型列表不能证明上传、提示词或生成参数受到限制。缺失规则、需求实现冲突、缺少用例和证据不足分开交付，不得一句“视频参数校验通过”掩盖。
