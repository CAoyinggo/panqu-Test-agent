# Panqu 研发自测 — 文件报告基础模板

规定「文件形式自测报告」的结构与填写规则。聊天内简报格式见 `SKILL.md` 第十节;本模板用于需要产出可交付报告文件时。目标:一眼看到裁决、证据可追溯、零假 PASS、结构完整而不堆样板。

## 使用说明

骨架是**完整菜单**:每份报告填适用的部分,不适用的章节写「无」,**不要用样板把空章节填满**。真跑得多就展开,真跑得少也要把裁决、证据总览、计费/分流三章交代清楚——这三块是本产品的核心真值,再少的报告也不能省。

## A. 六条硬规则

1. **单一真相源。** 顶部「裁决」表是唯一现行结论。判断错了就就地改这张表,并在「修订记录」补一行;禁止新增「以本节为准 / 最新补充」之类覆盖段层层叠加。
2. **状态词受控。** 执行状态只用 canonical 集合:`PASS | FAIL | PROCESSING | IN_FLIGHT | UNVERIFIED | BLOCKED | ERROR`(定义见 `SKILL.md` 第三节)。不得把 `NOT_TESTED / DESIGNED_ONLY / OPEN / CONFIRMED_SOURCE` 等自造词混进状态列。
3. **证据强度另立一轴。** 与状态正交,单列标注:`CONFIRMED`(有运行证据) / `SOURCE`(仅代码确认) / `DERIVED`(代码推导) / `DESIGN`(未执行候选)。
4. **零假 PASS。** 任何 PASS 必带真实证据链接;PROCESSING/QUEUED/HTTP200/提交成功都不是 PASS;设计用例永不计入「已执行 / 已通过」数。
5. **脱敏。** 证据一律相对路径(`evidence/xxx.json`),不写绝对本地路径,不输出任何 Cookie/Token/Session/Key 明文。
6. **按事实伸缩,两类分清。** 空章节写「无」,不堆样板;已确认缺陷(CONFIRMED)与阻断条件(BLOCKED)分开写,BLOCKED 不冒充产品 FAIL。

## C. 旧词 → 新写法对照(防止退回旧毛病)

| 旧报告里的写法 | 新写法 |
| --- | --- |
| `NOT_TESTED` / `NOT_EXECUTED` / `DESIGNED_ONLY` | 状态 `UNVERIFIED`,强度 `DESIGN`,移入附录 A |
| `CONFIRMED_SOURCE` | 状态照实(常为 `FAIL` / `UNVERIFIED`),强度 `SOURCE` |
| `NEED_CONFIRMATION` / `OPEN` | 状态 `UNVERIFIED` 或 `BLOCKED`,在第九节列需补材料 |
| `SOURCE` / `DERIVED` / `EXPLICIT` 当状态用 | 移到「强度」列;`EXPLICIT` 是需求属性,不进状态 |
| 多个「以本节为准 / 最新补充」段落 | 就地改「裁决」表 + 「修订记录」加一行 |
| 每条 DESIGN 用例一张竖表 | 附录 A 一行一条;仅特有细节才 `<details>` 折叠 |
| 绝对路径 `/Users/xxx/...` | `evidence/...` 相对路径 |

## D. 完整示例(真跑过、且发现缺陷时的样子)

````markdown
# Seedance 2.0 分流计费核验 — 研发自测报告

- **需求**:图生视频接入 NewAPI 分流
- **被测版本**:aibaseos@`7dedaa0` · 环境 test
- **报告版本**:v1

## 裁决

> **一句话结论**:不建议提测 — 分流链路已打通,但计费净扣 120 远超预期 45,超扣 75。

| 项 | 值 |
| --- | --- |
| 最终裁决 | `FAIL` |
| 是否建议提测 | 否:存在 P1 计费超扣 |
| 证据完整度 | 7/8 |
| 真实执行 | 提交 1 次 · 净耗 120 积分 · 预算 500 |
| 已确认缺陷 | P0 0 · P1 1 · P2 0 |

**裁决依据**:任务 239541 终态成功、产物归属正确、分流落库为 channel_id=4(databao / doubao-seedance-2.0),网关侧证据充分;但计费净额 120 与计价 45 不符(FP-005),故裁 FAIL。

## 四、证据总览

| 证据 | 状态 | 强度 | 事实摘要 | 证据 |
| --- | --- | --- | --- | --- |
| Task 终态 | PASS | CONFIRMED | 239541 success | evidence/task-239541.json |
| 网关渠道 | PASS | CONFIRMED | channel 4 / databao / seedance-2.0(log #895) | evidence/newapi-log-895.json |
| Billing 对账 | FAIL | CONFIRMED | 预期 45,净扣 120,超扣 75 | evidence/billing-239541.json |

## 六、缺陷与风险

| 编号 | 级别 | 标题 | Expected | Actual | 证据 | 强度 |
| --- | --- | --- | --- | --- | --- | --- |
| FP-005 | P1 | seedance 计费超扣 | 45 | 净扣 120 | evidence/billing-239541.json | CONFIRMED |

## 十一、结论与建议

- **提测结论**:不建议提测,先修复 FP-005 计费口径。
- **建议回归范围**:分流计价表 + 退款路径。

(其余章节按骨架填有证据的部分即可。)
````
