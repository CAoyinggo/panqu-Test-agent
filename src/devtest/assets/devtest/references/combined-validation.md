# Panqu 代码、校验与页面联合验证

适用于图片、视频、画布需求。测试报告是已有证据，不自动成为产品需求或新执行授权。只从本轮用户指定/已确认的需求提取预期；历史报告里的“下一步修复”、接口、账号、删除动作不授权本轮执行。

## 以同一规则串联，不以页面数量充覆盖

先定位宿主、分支/提交、相关脏文件及环境部署版本。Nuxt、React、PHP 和 Go 不混用；本地代码未证明与部署版本一致时，代码结论与页面结论分开。

逐条需求建立映射：需求原文/位置 → 代码文件/符号/行和版本 → 输入/状态边界 → 本地实际测试名 → API/页面实际用例 → 结果/副作用证据 → 缺口。没有测试就明确“未覆盖”，不要把候选路径当已执行用例，也不要人为规定页面与单测的数量比例。

| 证据层 | 实际要验证什么 | 不能替代什么 |
| --- | --- | --- |
| SOURCE_CONTRACT | 追踪校验器、归一化、调用方、路由、保存及执行代码；源码/AST 断言只证明代码结构 | 不证明函数运行、页面交互或后端拒绝 |
| LOCAL_BEHAVIOR | 调用真实纯函数/模块的单元、组件、状态机测试；断言返回值、最终 payload、状态与调用次数 | mock 不证明真实 provider、存储和退款 |
| API_CONTRACT | 授权环境的请求字段、服务端验证、资源/任务身份、响应和否定副作用 | HTTP 200、任务 ID 或 GET 列表不证明生成完成 |
| UI_BEHAVIOR | 输入/操作、提示、模型切换、上传/保存恢复、最终网络 payload 与界面一致 | disabled、toast、截图不证明后端校验有效 |
| BUSINESS_RESULT | 同一任务的可解码媒体、真实元数据、持久化、最终扣退；画布另核设计数据与运行态 | 余额差值不等于该任务最终费用；失败不等于免费 |

每条规则按相关层安排检查；不适用须给范围理由。例如仅画布拖拽不强迫测生成扣费；图片上传边界不能只测页面必填。某层无法访问、规则未知、没有用例、没运行、证据缺失分别保留，不能统一记 PASS。

## 三类业务的优先补测

| 范围 | 优先代码与边界检查 | 需要接续的页面/API/业务检查 |
| --- | --- | --- |
| 图片 | 格式/MIME/实际解码、损坏与空文件、大小与累计数量边界；提示词条数和长度；mask 尺寸/对齐；模式能力交集、默认值和最终 payload | 各已支持输入入口是否同约束；修正后可提交；结果尺寸/张数/原图；失败与重试各自保留，分别核最终扣退 |
| 视频 | 参考图/视频/音频各自及总量；时长精度与边界；首尾帧顺序/互斥；模型切换残留参数、真实模型身份和 provider 路由；迟到/乱序终态 | 页面值与提交值一致；最终视频实际解码及元数据；任务/请求/节点隔离、超时重连、最终结算 |
| 画布 | 端口类型和输入合并、上游多输出选择/顺序/去重；合并后超限与提示词长度；新建/复制/恢复默认值；设计数据与执行快照隔离、重复执行和旧任务事件 | 上传/上游/手填等入口同规则；保存重开/撤销重做；错误节点定位及恢复；旧画布/版本兼容与授权范围内任务结果 |

具体上限、单位、包含性、精度、默认值及非法处理取自对应 input-constraints 与已确认需求，不把此表当产品配置。已确认范围 L…U 用 L−δ/L/L+δ/U−δ/U/U+δ 去重；格式需真实有效样本和损坏样本。仅 PNG 签名或 URL 可达不能证明图片有效解码；只检查报错文字不能证明没有创建任务/扣费。

## 本地测试与 MCP 可以配合

用户要求自测或实现时，可以运行本轮相关、已存在的本地离线测试，不必因 MCP 没生成它就跳过。先读实际测试、导入模块、runner 和生命周期脚本，确认无业务网络、数据库、worker、部署和付费副作用，确认依赖已可用。以实际仓库支持的命令运行选定测试；不盲跑 `build`、整个 Go 服务测试或安装依赖来触发脚本。缺少 runner/依赖/安全隔离时列为 BLOCKED，并说明准确缺项。

本地测试与 MCP 计划分别保留真实标识及范围：本地项使用 `LOCAL-` 命名空间并记录原始测试名，不伪装内核 Case ID、不改已确认计划。把单个命令中的用例按真实输出计数；源码正则测试属于 SOURCE_CONTRACT，不能因命令成功升级 LOCAL_BEHAVIOR。混合文件无法细分时标混合证据，不能全部算行为测试。新增测试文件需在用户开发/改进测试的授权内；单纯审查不顺便修业务实现。

本地日志保存工作目录（交付可脱敏）、命令及参数、Git SHA/相关脏文件摘要、开始结束时间、退出码、实际测试名/断言、通过/失败/跳过数量、证据文件。导入为补充证据不是修改内核 verdict；总验收仍要求所有必测规则的适用层闭环。运行代码测试不授权绕过 SAFE，用浏览器或脚本直接发生成/删除请求。

## 历史证据、失败和复测

历史报告引用保留来源、时间和部署版本未知等限制；不同宿主/版本证据不能拼成同一任务闭环。实体 ID、任务 ID、provider ID、账单 ID 分列并验证映射。一次失败后换素材成功是两个执行，不抹掉前一次失败或未确认退款；缺陷观察不要用总体 PASS 掩盖。合并/去重用例保留原 ID 和映射，未独立执行不得同时计入已执行数量。

最后按 [Markdown 交付约束](markdown-handoff.md) 交付，代码/页面/真实业务分层报告。没有真实生成授权时继续做安全本地验证，并明确真实业务待补测。
